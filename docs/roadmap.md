# 『エスケープフロムダッコフ (Escape from Duckov)』開発ロードマップ

本ドキュメントは、アヒルを主人公にした見下ろし型3D脱出シューター『エスケープフロムダッコフ (Escape from Duckov)』を、大手ゲーム会社向けの「終活作品（ポートフォリオ）」として完成させるための全体俯瞰用ロードマップです。

アジャイル開発手法をベースとし、自社エンジン（`Baziru3_Engine`）を拡張する「エンジン層」と、ゲームプレイ・ギミックを構築する「アプリケーション層」に明確に切り分け、各フェーズの「ゴール」を固定して開発を進行します。

---

## 📅 開発フェーズの定義と主要マイルストーン

| フェーズ | 期間 (目安) | 主要成果物 / 目的 |
| :--- | :--- | :--- |
| **Prototype** | 6月中〜7月末 | 仮素材 (Greybox) でのコア面白さ検証・敵1体 |
| **Alpha** | 8月〜9月末 | 夏休み集中。全機能実装とゲームループ完成 |
| **Beta** | 10月〜11月中 | 本番アセット統合・手触りの磨き上げ (Polishing) |
| **Master** | 11月下〜12月 | 負荷対策・最適化・最終デバッグ・応募用動画撮影 |

---

## 🎯 各フェーズにおける詳細目標

### 1. Prototype フェーズ (6月中〜7月末)
**【ゴール】：「よちよち歩きでの照準・射撃・脱出」のコアプレイが面白いかを検証する。**

*   **エンジン層 (`Baziru3_Engine`)**
    *   コライダー形状の基礎拡充（カプセルコライダー、OBB判定のスタブ実装）
    *   3Dレイキャストの基礎実装（地形との接地判定、銃弾ヒットスキャンの準備）
    *   コライダーのデバッグ用ワイヤーフレーム描画機能
*   **アプリケーション層 (GamePlay)**
    *   アヒルのよちよち歩き（Waddle）物理（可変FPS下での移動・タイマー整合性の保証）
    *   マウス照準によるレティクル拡散（スプレッド）および連射反動システムの基礎
    *   簡易敵AI（Scav鴨）1体の配置とプレイヤー追跡・攻撃処理
    *   簡易脱出エリア（TriggerVolume）と脱出カウントダウン処理の検証

---

### 2. Alpha フェーズ (8月〜9月末)
**【ゴール】：ゲームループ（出撃 ➡ 探索・戦闘 ➡ 脱出 / MIAロスト）を完成させ、開発効率を高めるエディタを導入する。**

*   **エンジン層 (`Baziru3_Engine`)**
    *   ImGuiベースの「シーン配置エディタ」の実装（障害物や敵の配置をGUI上で変更し、JSONでセーブ＆ロード）
    *   DirectX 12 定数バッファのリングバッファアロケータ構築による描画オーバーヘッド削減
    *   オーディオ管理クラスの基礎拡張（複数のSE・BGMの同時再生とミキシング）
*   **アプリケーション層 (GamePlay)**
    *   7部位の個別HP（頭・胸・腹・手羽・両脚）および部位破壊ペナルティ（腕破壊でのエイムブレ激増、脚破壊での移動低下）
    *   壊死部位へのダメージ全身伝搬システム
    *   二重スタミナ管理（脚スタミナ ＆ 手羽スタミナ）
    *   タクティカルリロード ＆ スピードリロード（マガジン物理落下）
    *   敵AI（Scav鴨）の警戒段階FSM（パトロール・探索・戦闘・フランク）およびカバー＆ムーブ（遮蔽物利用ノード）
    *   多重脱出（制限時間、MIA時間切れロスト、条件付き脱出ロック）

---

### 3. Beta フェーズ (10月〜11月中)
**【ゴール】：本番アセットを統合し、没入感を生む3D音響や暗視などの特殊仕様を追加して手触りを磨き上げる。**

*   **エンジン層 (`Baziru3_Engine`)**
    *   3D音響オクルージョン（障害物や壁の材質・厚みに応じたリアルタイムなローパスフィルタ処理）
    *   閉鎖空間に応じた環境残響効果（インパルス応答 / リバーブサブミックス）
    *   敵AIパトロールルートエディタ（ウェイポイントをGUI上で視覚的に編集・接続）
*   **アプリケーション層 (GamePlay)**
    *   アタッチメント変更によるエルゴノミクス補正・スプレッド変動
    *   近接マズル干渉回避（銃身が壁に衝突した際の射撃ロックと回避ポーズ）
    *   暗視装置（NVG）およびサーマルスコープのポストプロセス（トーンマップ、ノイズ、自己発光ハイライト）
    *   出血による血痕（地面デカール生成）と治療システム（応急キット、副木による「よちよち治療」アクション）
    *   アヒルの鳴き声「クワッ (Quack)」の戦略的デコイ利用（音ノイズイベントによるAI誘導）
    *   地形マテリアル連動型の足音（アスファルト、鉄板、草地等）および水しぶきパーティクル
    *   扉の3Dインタラクション（ドア蹴り破り、ノックバック・スタン判定）

---

### 4. Master フェーズ (11月下〜12月)
**【ゴール】：ボトルネックを極限まで排除し、商業クオリティの最適化を施したポートフォリオとして完成させる。**

*   **エンジン層 (`Baziru3_Engine`)**
    *   空間分割（Grid/Octree）による衝突判定の高速化（$O(N^2)$ からの脱却、プロファイリング実証）
    *   GPUプロファイラUI（FPS、描画コール数、CPU/GPU処理時間をリアルタイムにグラフ描画）
*   **アプリケーション層 (GamePlay)**
    *   リザルト画面での被弾・弾着部位の3Dアヒルモデルへのマッピング（どの部位にどの弾が当たったかを可視化）
    *   ゲーム全体の徹底的な負荷対策・メモリリーク検出・バグフィックス
    *   大手ゲーム会社提出用の「ゲームプレイ動画」および「技術アピール（自社エンジンの機能・最適化）解説動画」の撮影・編集

## 🛠️ アジャイル開発運用ルール

本ロードマップを実効性のあるものとするため、以下の運用ルールをタスクリスト（`tasklist.md`）と合わせて適用します。

1.  **「4時間（1ユニット）」ルール**
    *   タスクリストに登録する作業はすべて最大4時間以下に分解します。
    *   5時間を超えるタスクは「分解不足」とみなし、より具体的な実装ステップに細分化します。
2.  **「2倍バッファ」ルール（遅延対策）**
    *   見積もり時間の2倍（最大8時間）が経過した時点で進捗が完了しない場合、そのタスクの実装アプローチを見直すか、仕様を簡略化（デスコープ）して進行します。
3.  **優先度（Must / Should）順のキュー管理**
    *   依存関係（エンジン層 ➡ アプリケーション層）を考慮し、必ず必要な機能（Must）から順番に一本のキューとして並べ、上から順に消化していきます。
