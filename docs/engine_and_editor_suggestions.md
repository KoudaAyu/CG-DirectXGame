# エンジン層の強化およびエディタツールの開発提案

本ドキュメントは、現在構築されているゲームエンジン（`Baziru3_Engine`）およびアプリケーションの完成度をさらに高め、ポートフォリオとしての価値とゲーム開発効率を劇的に向上させるための具体的な提案をまとめたものです。

---

## 1. エンジン層（`Baziru3_Engine`）の改善案

### ① 空間分割（Broad-Phase）による衝突判定の高速化
現在、`CollisionManager` はすべてのコライダーを総当たり（$O(N^2)$）で判定しています。オブジェクト数が数百個に増えるとCPUに大きな負荷がかかるため、以下の導入を提案します。
* **グリッド分割法 (Grid Partitioning)**：空間を一定サイズ（例: 10m 四方）のセルに分割し、同じセルまたは隣接するセルにあるコライダー同士のみを判定対象とします。
* **八分木 (Octree)**：3D空間を再帰的に8分割してノード単位で衝突判定の枝刈りを行います。

### ② コライダー形状の拡充（OBB, Capsule）
現在スタブ（未実装）になっている交差判定関数を実装することで、ゲームの表現力を広げられます。
* **OBB (Oriented Bounding Box) 同士の判定**：回転する障害物や複雑な箱型オブジェクトに対応するため、分離軸定理（SAT）を用いた判定を実装します。
* **カプセル vs カプセルの判定**：線分同士の最短距離計算を用いて、プレイヤーと敵の「カプセル同士の滑らかな接触」などを表現できるようにします。
* **レイキャスト (Raycast) 関数の追加**：`CollisionManager::Raycast(const Vector3& origin, const Vector3& dir, RaycastHit& hit)` を実装し、地面との接地判定や銃弾の瞬時着弾（ヒットスキャン）に利用できるようにします。

### ③ 定数バッファのメモリ管理最適化 (リングバッファアロケータ)
DirectX 12 では、毎フレームリソースを生成（`CreateCommittedResource`）するとメモリ確保オーバーヘッドが大きくなります。
* 起動時に一括で巨大なバッファ（例: 1〜2MB）を確保し、そこから毎フレーム必要な領域をリングバッファ形式で切り出すアロケータを構築することで、描画処理の高速化を図ります。

## 2. エディタ層（開発ツール）の提案

ImGui などを利用したデバッグ UI / エディタを構築する場合、以下のツールがあるとゲーム制作が格段に快適になり、技術的なアピールポイントとしても強力です。

### ① コライダー・デバッグビジュアライザ
* **機能**：ゲーム画面上に、設定されている `SphereCollider` や `BoxCollider` の形状をワイヤーフレーム（緑色や赤色）で重ねて描画する機能です。
* **メリット**：コライダーのサイズや位置が意図通りに機能しているか、一目で確認できるようになります。

### ② シーン配置エディタ (Scene Editor)
* **機能**：ゲーム内の障害物（`Obstacle`）や敵の配置を、ゲームを実行したまま GUI 上で変更できるエディタです。
* **実装内容**：
  - オブジェクトを選択し、ImGui のスライダーやギズモ（マウスドラッグ操作）で Position / Rotate / Scale を調整。
  - 配置したデータを **JSON などのファイルとしてワンクリックで保存（セーブ）＆読み込み（ロード）** できるようにする機能。
* **メリット**：コード上の数値を書き換えて再ビルドする手間がなくなり、レベルデザインが瞬時に行えるようになります。

### ③ 敵 AI パトロールルートエディタ
* **機能**：`MovingEnemy` が移動する経路（`patrolA_`, `patrolB_` などの巡回ポイント）を視覚的に追加・編集できるツールです。
* **実装内容**：画面上に巡回用のウェイポイント（点）を表示し、マウス操作で点を移動させたり、リンク線で繋いで移動ルートを設計します。

### ④ プロファイラー UI (Performance Profiler)
* **機能**：フレームレート（FPS）、描画コール数（Draw Calls）、CPU/GPUの処理ミリ秒数を折れ線グラフでリアルタイム表示します。
* **メリット**：最適化が必要なボトルネック（描画処理が重いのか、物理判定が重いのかなど）を視覚的に特定できるようになります。
