# 🎯 セガ ポートフォリオ戦略ガイド
### "Escape from Duckov" を最大限に魅せるために

---

## 結論から言うと

> **「ボリュームより、1つ1つの完成度と技術の見せ方」が正解。**

セガのようなプロのデベロッパーは、「できること」の量より  
**「なぜそう設計したか」を語れる力** を評価します。

---

## 🔍 セガが採用で見るポイント

| 評価軸 | 具体的に見ていること |
|---|---|
| **技術力** | 自作エンジン・カスタムシステムが動いているか |
| **設計力** | コードが整理されているか（責務分離・拡張性） |
| **ゲームデザイン力** | ゲームとして「遊べる」「面白い」か |
| **問題解決力** | 詰まった時にどう解決したかを説明できるか |
| **完成への意志** | 未完成・放置プロジェクトが多くないか |

---

## 📊 現状の強みと弱み分析

### ✅ 強み（そのまま推せるポイント）

#### エンジン層（超高評価）
- **DirectX 12 完全自作エンジン `Baziru3_Engine`**  
  シェーダー、定数バッファ、GPU粒子、スキニングを自前実装
- **BehaviorTree + NavMesh の AI システム**  
  JSON から動的ロード、フォールスルー機構付き
- **アトミック JSON セーブ (`JsonSafeLoader`)**  
  本番品質の IO 安全対策が実装済み
- **CCD 弾丸衝突 + LOS 遮蔽チェック**  
  CollisionSystem.cpp の実装は相当本格的
- **型安全 Scene Context**  
  std::any テンプレートによる型安全シーン間データ受け渡し
- **GPU パーティクル（血しぶき・火花・煙）**

#### ゲームデザイン層
- Tarkov オマージュの戦術性（遮蔽・弾薬管理・脱出）
- スタミナ・リロード・救急キットの複合リソース管理
- 照準拡散システム（移動 / 静止で変化）

---

### ⚠️ 弱み（改善すると化けるポイント）

| 弱点 | 影響度 | 修正コスト |
|---|---|---|
| 敵が2体しかいない | 高（遊べない印象になる） | 低〜中 |
| サウンドが薄い or なし | 高（手触りの悪さに直結） | 低 |
| プレイしてすぐ終わる（ゲームループが短い） | 中 | 中 |
| ポートフォリオのドキュメント整備 | 高（見せ方の問題） | 低 |

## 🚀 提出までにやるべきこと（優先順位付き）

### Priority 1：絶対やる（提出品質に直結）

#### ① サウンドエフェクトを追加する
```
射撃音 / 被弾音 / リロード音 / 足音 / 脱出成功ジングル
```
AudioManager はすでに GamePlayScene に組み込み済み。  
ゲームの「手触り」が劇的に変わる。

#### ② 敵を最低でも 3〜4 体にする
既存の MovingEnemy を使い回すだけで実装可能。  
巡回ルートを変えるだけで戦術の幅が広がる。

#### ③ 標的破壊後の「増援スポーン」を追加する
```
フェーズ1: 標的3個を破壊
フェーズ2: 「増援が来た！」→ 敵2体が新規スポーン  
フェーズ3: 敵を倒して脱出ゾーンへ
```
allTargetsDestroyed_ フラグ検知時に追加スポーンするだけ。  
ゲームとしての緊張感・クライマックス感が生まれる。

#### ④ README・ドキュメントを整備する
技術の深さがあっても、説明できないと評価されない。

**README.md に書くべきこと:**
- ゲーム概要 + 操作説明
- 自分が実装した技術リスト（エンジンから書く）
- 苦労した点・解決方法
- 参考・非参考の明示
- ビルド方法

> **注意:** 「何を自分で実装したか」を明確に書くこと。  
> assimp・ImGui・nlohmann との区別を明示しないと  
> 評価者が判断できず、低評価になる可能性があります。

---

### Priority 2：やるとさらに良くなる

#### ⑤ カメラを照準方向に微オフセット
プレイヤーとマウスカーソルの中間点にカメラを追従。  
「前が見やすい！」という操作感が劇的に上がる。

#### ⑥ 敵の「発見警戒演出」（0.5秒の硬直→射撃）
- 「！」マーク表示 → 警戒硬直 → 射撃
- BehaviorTree に警戒フェーズを追加するだけ
- 「戦術的に立ち回れる」ゲームになる

#### ⑦ HUD に「カバー中」「照準安定」の状態表示
isInCover_ と currentSpread_ はすでに存在している。

---

### Priority 3：時間があれば（差別化ポイント）

#### ⑧ 武器切替システム（AK / MP5 / ショットガン）
- GameConfig.h に武器パラメータを追加
- Player に weaponIndex_ を持たせるだけ

#### ⑨ ルートのランダム配置（再プレイ性向上）
- JSON 座標 + ランダムオフセット
- 毎プレイ異なる体験になる

## 🎬 「見せ方」が一番大事

ゲームを作るのと同じくらい、**「どう見せるか」** が採用に直結します。

### やること
- プレイ動画を録画して YouTube（限定公開）か GitHub に載せる
- README に自分が実装した技術の一覧を書く
- 難しかった技術課題とその解決策を1〜2個深く書く
- コードの汚い部分はリファクタリングしてから見せる

### やってはいけないこと
- 未完成のまま「作りかけです」と出す
- 「ボリューム」を増やすために急いで粗いものを量産する
- 他人のコードを自分のものとして出す（必ず出典を書く）
- ビルドが通らない状態で出す
