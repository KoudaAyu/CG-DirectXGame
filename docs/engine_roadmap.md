# エンジン層開発ロードマップ (TOSE対策・ポートフォリオ強化用)

このロードマップは、コンソールゲームの開発受託最大手である「トーセ（TOSE）」をはじめとするゲーム会社に、技術力を強くアピールするためのエンジン層強化チェックリストです。優先度が高く、かつ細分化されたタスクに分かれています。

---

## 1. メモリ管理の最適化 (Custom Allocators)
**最優先（評価に直結）：ゲーム実行中の動的メモリ確保（new/delete, std::vectorの自動拡張）によるフレームレート低下を回避する仕組みを作ります。**

### [ ] 1.1. 定数バッファ（CBV）用リングバッファアロケータの構築
- [ ] **バッファの一括確保**: 毎フレームの `CreateCommittedResource` を廃止し、起動時に大きめのアップロードバッファ（例: 1MB）を1枚生成する。
- [ ] **アライメント計算**: DirectX 12の定数バッファ要件である「256バイト境界」に合わせてアドレスを前進させるアライメント関数を実装する。
- [ ] **リングバッファ管理**: 現在の書き込みオフセット（ポインタ）を管理し、末尾に達したら先頭に戻るループ処理を実装する。
- [ ] **フェンス同期**: ダブル/トリプルバッファリングを考慮し、GPUがまだ描画中の領域をCPUが上書きしないよう、完了フェンス値（Fence Value）とリングバッファの進捗を同期・待機させる仕組みを実装する。

### [ ] 1.2. 短寿命オブジェクト用スタックアロケータの実装
- [ ] **プール領域の確保**: 起動時に一定サイズのメモリ領域（例: 1〜2MB）を確保する。
- [ ] **高速アロケート**: ポインタ（オフセット）を指定されたサイズ分だけ進めてメモリ領域を返す単純・超高速な `Allocate` を実装する。
- [ ] **一括リセット**: フレームの開始時や終了時に、オフセットを `0` に戻すだけで全メモリを解放扱いにする `Reset` を実装する（要素個別の `delete` は行わない）。

### [ ] 1.3. 同一サイズ用プールアロケータの実装
- [ ] **フリーリスト管理**: コライダーやパーティクルなどの最大生成数に応じたメモリ領域を確保し、未使用オブジェクトのインデックスを連結リスト（フリーリスト）で管理する。
- [ ] **O(1)の生成・破棄**: フリーリストから要素を取り出すだけの `Allocate`（$O(1)$）と、フリーリストに戻すだけの `Free`（$O(1)$）を実装する。

## 2. 衝突判定の最適化 (Collision Optimization)
**優先度：高：オブジェクト数が数百〜数千になっても処理落ちしないための空間分割と、CPUキャッシュを意識した設計を行います。**

### [ ] 2.1. 空間分割（八分木: Octree または グリッド）の導入
- [ ] **境界ボックスの定義**: ゲームワールド全体の大きさを表すバウンディングボックスを設定する。
- [ ] **八分木クラスの作成**: 空間を再帰的に8分割する `OctreeNode` 構造を作成する。
- [ ] **動的登録処理**: 毎フレーム、全コライダーの現在位置（AABB）から所属するノードを判定・登録する処理を実装する。
- [ ] **衝突候補の抽出 (Broad-phase)**: 同一のノード、および親・子ノードに所属するコライダー同士だけを判定対象リストとして抽出する関数を実装し、総当たり回数を減らす。

### [ ] 2.2. データ指向設計（DOD）に基づくメモリ配置
- [ ] **判定用軽量データ構造体**: 仮想関数や複雑な親子関係を持たない、判定に必要なデータ（AABB、Sphereの中心座標・半径・IDなど）のみを並べた構造体 `CollisionData` を定義する。
- [ ] **連続メモリ配置**: `CollisionManager` 内で `CollisionData` の動的配列（`std::vector`）を保持し、メモリ上で連続するよう配置する。
- [ ] **高速バッチ処理**: メモリアクセスのキャッシュミス（Cache Miss）を最小限にするため、連続配列を単純なループでイテレートして一括で判定・解決するロジックに書き換える。

## 3. アセットパイプラインのバイナリ化と非同期ロード
**優先度：中〜高：実務のゲーム開発における「ロード時間の極小化」と「マルチスレッド処理」の実践を示します。**

### [ ] 3.1. 独自バイナリフォーマットへのコンバータ作成
- [ ] **コンバータの実装**: アセット（FBXやJSONなど）を解析し、頂点・インデックス・マテリアル・アニメーションデータをパース不要なバイナリ構造体の羅列に並び替えるオフラインツール（C++またはPython等）を作成する。
- [ ] **一括読み込み**: エンジン側のロード処理で、バイナリファイルを `std::ifstream::read` などで一括でメモリバッファにロードし、構造体ポインタにキャストするだけでデータ復元できる仕組みを実装する。

### [ ] 3.2. 非同期ロード（マルチスレッド）の導入
- [ ] **ロードタスクキュー**: ロード要求を受け付けるスレッドセーフなキューを作成する。
- [ ] **バックグラウンドスレッド**: ロード要求キューを監視し、別スレッド（`std::thread`）でファイルを非同期で読み込むワーカースレッドを実装する。
- [ ] **GPU転送の同期**: バックグラウンドスレッドで読み込んだテクスチャやバッファデータを、メインスレッド側の描画処理と衝突しないように安全にGPUにアップロード・同期する仕組み（CommandQueueの同期）を実装する。

## 4. DirectX 12の機能を活かしたグラフィックス強化
**優先度：中（グラフィックス志望なら最優先）：GPUの仕組みへの深い理解をアピールします。**

### [ ] 4.1. ディスクリプタヒープ（Descriptor Heap）マネージャの構築
- [ ] **メガヒープの確保**: SRV/UAV用に大きな DescriptorHeap（例: 2048スロット）を起動時に1つだけ確保する。
- [ ] **スロットアロケータ**: 使用中・未使用のスロットインデックスを管理し、新しいテクスチャが読み込まれた際に動的にスロットを切り出す仕組みを実装する。
- [ ] **メガヒープの一括バインド**: 描画開始時にこのヒープのみをコマンドリストにバインドし、描画ごとのヒープ切り替えオーバーヘッドを削減する。

### [ ] 4.2. カスケードシャドウマップ（CSM）の実装
- [ ] **テクスチャ配列の作成**: シャドウマップ用のテクスチャ配列（`Texture2DArray`）および対応するDSV（Depth Stencil View）群を作成する。
- [ ] **視錐台の分割**: プレイヤーカメラの視野（Frustum）を深度に応じて近景・中景・遠景の3〜4段階（Cascade）に分割する。
- [ ] **ライト射影行列の計算**: 分割された各エリアをすっぽり囲むように、ライト視点での正射影行列を毎フレーム計算する。
- [ ] **マルチパス描画**: シャドウマップパスで、それぞれの階層に応じたライトビュープロジェクション行列を用いて深度を描画し、メインパスで補間して影を落とす。

## 5. デバッグ・計測基盤の構築
**優先度：中：「感覚」ではなく「数値」に基づいてボトルネックを特定し、最適化できるエンジニアであることを証明します。**

### [ ] 5.1. GPUタイムスタンプクエリによる処理時間計測
- [ ] **クエリヒープの作成**: `D3D12_QUERY_HEAP_TYPE_TIMESTAMP` タイプのクエリヒープを作成する。
- [ ] **タイムスタンプ挿入**: 各描画パス（シャドウパス、メインパス、ポストエフェクト等）の開始時と終了時に `EndQuery` をコマンドリストに積む。
- [ ] **データの解決と計算**: フレームの最後に `ResolveQueryData` でクエリ結果を読み取り用バッファに転送し、GPU周波数を用いて処理時間（ミリ秒）を計算する。
- [ ] **UIビジュアライズ**: 計測した各パスのミリ秒を、ImGuiのグラフやバーチャルタイムラインとして画面上に描画する。
